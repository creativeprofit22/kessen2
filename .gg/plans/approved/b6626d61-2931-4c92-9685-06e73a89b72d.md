## Dependency rule (documented in ARCHITECTURE.md + ADR-0004, enforced in CMake)
| Module target | May link |
|---|---|
| `k2_platform` | SDL3 only |
| `k2_render` | `ps2_runtime` (GSRasterBackend/VU interfaces), `k2_platform` |
| `k2_runtime_ext` | `ps2_runtime` |
| `k2_generated` (only created when `generated/` has sources) | `ps2_runtime` |
| `kessen2` (app) | all of the above |

Enforcement (`cmake/K2Modules.cmake`):
- `k2_add_module(<target> ALLOWS <targets…>)` records an allowlist property.
- `k2_verify_module_graph()` (called last in root CMakeLists) walks `LINK_LIBRARIES` + `INTERFACE_LINK_LIBRARIES` transitively for each k2 target → `FATAL_ERROR` on any k2/generated edge not in its allowlist; also fails if `K2_GENERATED_DIR` appears in `INCLUDE_DIRECTORIES` of `k2_platform`/`k2_render`/`k2_runtime_ext`.
- `tools/guard/check-forbidden.sh` additionally greps `platform/` and `render/` sources for includes of generated headers (`ps2_recompiled_*`, `generated/`) — catches relative-path includes CMake can't see.
- CTest `k2_dep_rule_negative`: configures `tests/cmake/dep_violation` (tiny project using K2Modules.cmake where `k2_platform` links a fake `k2_generated`) and expects failure (`WILL_FAIL`).

## Git guardrails
- `.gitignore`: `*.iso *.bin *.img *.cue *.mdf *.mds *.nrg *.cso *.chd`, `*.elf *.ELF SLUS_* SLES_* SLPM_* SLPS_* SCUS_* SCES_* SCPS_*`, `*.irx *.IRX`, `work/ extracted/ dump/ dumps/ assets_dumped/`, `generated/*` + `!generated/README.md`, `*.gzf *.rep` Ghidra projects, `build/ out/`, `*.mc2 *.ps2` memcards.
- `tools/guard/check-forbidden.sh [--staged|--all]`: fails on (a) forbidden path/extension patterns, (b) content magic — ELF `\x7fELF`, ISO9660 `CD001` at offset 0x8001, PS2 memcard header, (c) any file > 20 MB, (d) generated-include rule above. POSIX sh + git only (runs in Git-for-Windows hook shell and Linux CI).
- `tools/guard/pre-commit` calls it with `--staged`; `install-hooks.sh` **copies** it into `.git/hooks/` (no `git config` changes).
- `.github/workflows/guard.yml` runs `check-forbidden.sh --all` on push/PR.
- `tools/guard/test_guard.sh`: creates a temp git repo, stages synthetic fake ISO/ELF/`generated/x.cpp`, asserts the check fails, then asserts a clean file passes. Registered as CTest `k2_guard`.

## Superbuild
- Root `CMakeLists.txt`: `cmake_minimum_required(3.21)`, C++20, options `KESSEN2_WITH_PS2RECOMP` (ON), `KESSEN2_GENERATED_DIR` (default `${CMAKE_SOURCE_DIR}/generated`).
- With PS2Recomp: set `PS2X_BUILD_ANALYZER/TEST/STUDIO OFF`, `PS2X_BUILD_RECOMP ON` (tool needed in Phase 4), `add_subdirectory(external/PS2Recomp EXCLUDE_FROM_ALL)`.
- SDL3 via `FetchContent` `release-3.4.16` (`SDL_SHARED ON`, tests/examples off); copy DLL next to `kessen2.exe` post-build.
- `CMakePresets.json`: `msvc-x64` (VS 17 2022, x64, binaryDir `out/build/msvc-x64`), build presets Debug/Release, test preset.
- Fallback if upstream PS2Recomp fails to build on MSVC 14.44 / CMake 4.4: try `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`; if still broken, record the error in docs/DEPENDENCIES.md, pin the newest commit that builds, and keep `KESSEN2_WITH_PS2RECOMP=OFF` path building the stubs so the criterion is still met honestly.

## Verification criteria
1. `cmake --preset msvc-x64` configures; `cmake --build --preset msvc-x64-debug` builds `k2_platform`, `k2_render`, `k2_runtime_ext`, `kessen2`; `kessen2.exe --version` prints SDL version and exits 0.
2. `ctest --preset msvc-x64` passes `k2_dep_rule_negative` and `k2_guard`.
3. Manually adding `target_link_libraries(k2_platform PRIVATE k2_runtime_ext)` makes configure fail (then reverted).
4. `git submodule status` shows the pinned SHA matching DEPENDENCIES.md; `git status` shows everything staged, no commit made.
5. `tools/guard/check-forbidden.sh --all` passes on the real tree; `git check-ignore` confirms `foo.iso`, `SLUS_123.45`, `generated/a.cpp`, `work/x` are ignored.
